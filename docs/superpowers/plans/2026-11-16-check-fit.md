# Check a job's fit, and a Follow-ups count: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the Jobs page the owner can paste a job (or a link), get an AI fit judgment with a model of their choice, decide what to do with it, optionally create documents, with everything recorded in the tracker; and the menu shows how many follow-ups are overdue or due today.

**Architecture:** Two independent parts. Part 1 adds a small counts endpoint and a menu pill that refetches on events. Part 2 adds two API calls (`check` reads and saves the job; `fit` judges it) built from the existing extraction and scoring functions, and a Jobs-page panel that reuses the existing status and documents controls. No database schema change.

**Tech Stack:** Python 3.12, FastAPI, SQLModel; React 19 with TypeScript, Vitest; the repo's `FakeProvider` for backend tests.

**Spec:** `docs/superpowers/specs/2026-11-16-check-fit-design.md`

**Delivery:** Two pull requests (`main` is protected; every PR runs CI). Tasks 1-2 are Part 1 and go first as their own PR. Tasks 3-8 are Part 2, on a branch stacked on Part 1 until it merges. Task 8 is a live gate with the owner present.

## Global Constraints

- No database schema change. Use the job's existing `match_score`, `reasons`, `gaps`, `flags`, `hard_rules`, `liveness`, `notes`, `description`, `apply_url`, `source` and the activity log. New jobs have `origin="manual"` and `status="New"`.
- Reading a posting always uses the **Extract** step's provider and model. Only the fit judgment uses the owner's dropdown choice.
- The dropdown offers the distinct `(provider_id, model)` pairs configured across the five steps, labelled from `STEP_INFO`, with the **score** step first and marked default. A request names a *step id*, never a model string.
- A check fetches a link with a **10-second** timeout (`CHECK_FETCH_TIMEOUT = 10`), never LinkedIn or a non-public address, and reads at most **30,000** characters of pasted text. A page yielding fewer than **300** characters is "unreadable".
- Two AI calls at most per check, no tools, existing fixed-schema functions only (`extract_posting`, `score_job`); any schema must set `additionalProperties: false` (`tests/test_schemas.py`).
- Each fit writes an activity-log entry naming the model and the approximate cost.
- Hard-rule failures and warnings are shown, never blocking.
- Nothing personal in the repo: tests and docs use made-up names (`example.com`, "Northwind Labs"); `tests/test_docs.py` scans for personal data.
- Frontend: `npx tsc -b`, `npm run lint`, `npm test` and `npm run build` must pass before each commit; text files use LF.
- Every commit message ends with the line `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

Failure modes the spec implies that the tests must exercise, most likely first. Each has a test in the task that owns the code.

1. **A pasted posting that is mostly page chrome, very short, or a script-built page with almost no text.** It must give a plain "paste the text" or "couldn't find the employer and title" message and create nothing. (Task 4.)
2. **A job already in the tracker, in a different spelling:** a link with a trailing slash or different case, the same requisition with a reworded title. The existing job is shown, nothing is created. A second quick check of the same job must also return the duplicate. (Tasks 3, 4.)
3. **Hostile or enormous pasted text** (instructions aimed at the model, 200,000 characters). It is capped, goes only to the fixed-schema calls, and cannot start documents or change anything. (Task 4.)
4. **The AI failing, or being asked again.** A failed read creates nothing; a failed fit keeps the saved job and any earlier fit untouched; a re-check overwrites cleanly without piling up flags. (Task 5.)
5. **The Follow-ups count at its edges:** overdue, due today, due tomorrow, done, cancelled, and a follow-up created by marking applied (due in 7 days, not counted yet), all by the app's own "today". (Task 1.)
